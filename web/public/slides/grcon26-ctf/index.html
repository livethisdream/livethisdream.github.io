    SigID · WBFM

    GQRX→ WFM stereo→ left / right / RDS panel
    • Flags in L, R, and RDS
    • GQRX in WFM stereo mode; RDS in its RDS panel
    • Mono sums L and R into one mess

    Eleven carriers, fourteen flags. Stop counting at eleven and three flags stay on the table.

    Every carrier runs at once and loops for the whole recording, so a player can tune anything at any time and hear a complete pass. The metadata carries no annotations: labeling the slots would hand over the signal list, which is the challenge. Hint 1 told players to put the whole span in a waterfall first. The expected route opens the recording in GQRX (or SDR++) as a file source and clicks through the carriers; that is the expected route, not one we ran end to end. The data slots share one back end: GQRX’s UDP audio stream, resampled with sox and piped into multimon-ng, with only the decoder changing from slot to slot (Morse, DTMF, POCSAG, FLEX, EAS). Our check is sigid/verify.py, which channelizes every slot out of the shipped composite.

    The wide carrier sits at −140 kHz, 200 kHz wide, at the bottom of the span. Pick WFM (stereo) in GQRX. Headphones put flag 6 in the left ear and flag 7 in the right, each a spoken NATO-phonetic value; recording the audio and splitting the channels in Audacity separates them cleanly. WFM mono sums left and right, so the two voices talk over each other. Turn on GQRX’s RDS decoder in the same mode and RadioText reads flag8{…}. The Program Service name reads NUMBERS and carries no flag; we rejected PS as a fourth flag because it comes out of the same decoder run.

    Under the hood, for a player building it in GNU Radio: a quadrature discriminator gives the multiplex; the 19 kHz pilot is phase-locked to the 38 kHz subcarrier by construction, so squaring the band-passed pilot gives a coherent 38 kHz reference with no PLL; product-detecting L−R against it and unmixing with L+R gives left and right. RDS sits on a 57 kHz DBPSK subcarrier at 1187.5 bps. verify.py passes this slot on the RDS text and writes the left and right audio out for listening; the author listened to both after demodulating them back out of the composite. The stereo and RDS flags stayed at 25 points each by design so one carrier does not score three times the rest.

    Stay Gold · DSSS with a Gold Code

    GQRX CW→ multimon-ng→ name → Gold code→ acquire script→ GRC despread→ DBPSK→ frames
    1. Floor half a dB high across ±100 kHz: spread signals under it
    2. Hint: a twenty-bit code; the title says Gold
    3. Crockford base32: … is 20 bits, G1 fill 247, G2 fill 628
    4. Taps 1+x^3+x^10 and 1+x^2+x^3+x^8+x^10; clock 1023 chips; XOR; send as ±1

    The raised floor across ±100 kHz has edges a chip rate apart, measurable on GQRX’s FFT or in inspectrum: 100 kchip/s. The player hint says the name is a twenty-bit spreading code and that everything else is in the title, and Stay Gold points at a Gold code. From here the route is custom code, which is the challenge.

    Four Crockford base32 characters (alphabet 0123456789ABCDEFGHJKMNPQRSTVWXYZ, five bits each) are 20 bits, split into two 10-bit register fills: the top ten bits fill G1, the bottom ten fill G2. … gives G1 fill 0011110111 = 247 and G2 fill 1001110100 = 628. The decode is case-insensitive and ignores hyphens, and Crockford already folds I/L to 1 and O to 0, so a misread ident still lands on the same fills. An all-zero fill is a dead code; our name_to_fills rejects it.

    The polynomials are the standard 1023-chip pair, G1 = 1 + x^3 + x^10 and G2 = 1 + x^2 + x^3 + x^8 + x^10: the same G1 as GPS C/A, a different mate, on purpose, so there is no navigation message to go hunting for. The fill’s MSB goes into stage 1, the output taps stage 10, and the code is the XOR of the two register outputs, sent as +1/−1. The generator is a dozen lines of Python; this is the one in stay_gold/stay_gold_acquire.py, and the flowgraph carries the same function in a Python Module block named gold_code:

    CROCKFORD = "0123456789ABCDEFGHJKMNPQRSTVWXYZ"

def lfsr(taps, fill):
    reg = [(fill >> (9 - b)) & 1 for b in range(10)]      # MSB into stage 1
    out = []
    for _ in range(1023):
        out.append(reg[-1])                                # output is stage 10
        fb = 0
        for t in taps:
            fb ^= reg[t - 1]
        reg = [fb] + reg[:-1]
    return np.array(out)

def gold(name):
    v = 0
    for ch in name.upper():
        v = v * 32 + CROCKFORD.index(ch)
    bits = lfsr((3, 10), v >> 10) ^ lfsr((2, 3, 8, 10), v & 0x3FF)
    return 1.0 - 2.0 * bits                                # 0/1 -> +1/-1

    Our check on the pair is structural, not a comparison against our own generator: the cross-correlation between family members takes exactly three values, {−65, −1, 63}, which is what a preferred pair gives and a non-preferred pair does not (11 values in our test). The flowgraph’s generator matches stay_gold/gold.py chip for chip.

    Stay Gold · Find the Code Phase

    GQRX CW→ multimon-ng→ name → Gold code→ acquire script→ GRC despread→ DBPSK→ frames
    1. Hold each chip for 4 samples: one code period is 4092 samples
    2. FFT-correlate per 4092-sample block, ifft(fft(block)·conj(fft(code))); keep the max over blocks
    3. stay_gold_acquire.py <capture> …: lag 1373, peak 6.2× the median
    4. Epoch 0 chips for a named code; Skip Head = 1373
    5. Wrong name V4RX: 1.9×, noise

    The capture starts at an arbitrary point in the code, and a flowgraph has no stock block that searches 4092 alignments, so this step is a short numpy script: build the code, hold each chip for 4 samples (100 kchip/s at 4 samples per chip; 1023 chips make a 4092-sample period, one data bit per period, 97.75 bit/s), and circularly correlate it against one code period of the capture at a time with an FFT, ifft(fft(block) · conj(fft(code))). The score for an offset is the best block, not the sum: a block that straddles a data transition loses part of its peak to cancellation, and with differential data about half of them do, so max-over-blocks keeps the clean ones. The peak’s index is the code phase. A second pass picks the symbol epoch, the chip shift at which every symbol correlates to full height; for a named code it is zero, because a name gives the code at rotation zero, and the blind-sweep frame says why that matters.

    stay_gold/stay_gold_acquire.py is that script, numpy only, written the way a player would write it (it is the repo’s, not one shipped to players; a player writes the same twenty lines). It prints the Skip Head value for the flowgraph:

    python3 stay_gold_acquire.py <capture> …
# code …: lag 1373, peak/median 6.2, epoch 0 chips
# Skip Head = 1373 samples

python3 stay_gold_acquire.py <capture> V4RX
# code V4RX: lag 1233, peak/median 1.9, epoch 150 chips

    The second run is the wrong-code control: V4RX is a valid name that was never transmitted, and its best offset stands 1.9× the median against 6.2× for …, which is what a correlation against noise looks like. Our verifier runs the same control and gets 0 frames from it: the code is load-bearing, not decorative.

    Stay Gold · Differential BPSK Decode

    GQRX CW→ multimon-ng→ name → Gold code→ acquire script→ GRC despread→ DBPSK→ frames
    1. Constellation Sink: a ring, radius 141, turning 22° per symbol
    2. Delay 1 and Multiply Conjugate form s[n]·s*[n−1]: the spin cancels
    3. Complex to Real, Multiply Const −1, Binary Slicer: a flip is a 1
    4. Time Sink: steady ±18,000 bars mean locked; noise, wrong code or phase

    These are the flowgraph’s own two plots, from GNU Radio 3.10.9.2 running stay_gold/stay_gold_despread.grc on the shipped capture with … at skip 1373. The Constellation Sink on the Integrate output shows the literal symbols s[n]: magnitude about 141, and a phase that advances about 22° per symbol, a residual carrier offset of roughly 6 Hz at 97.75 symbols per second, from a random starting phase. Plain BPSK would need a carrier-recovery loop to pin that ring down to two points before slicing.

    Differential BPSK puts the bit in the change of phase instead. Multiply Conjugate against a one-symbol Delay forms s[n]·s*[n−1]: the unknown phase cancels, and the 22° step only shrinks the result by cos 22°, so the bars sit near 141² × 0.93 ≈ 18,400. The Multiply Const −1 before the plot and the slicer makes a phase flip positive, so a bar near +18,400 is a 1 and one near −18,400 is a 0. Differential encoding gives up about a dB and removes two stages: no carrier phase recovery, and no 180° ambiguity to resolve. With 15 dB of margin after despreading that is the right choice for a challenge where the player writes the receiver.

    Stay Gold · Frames and the NEXT Field

    GQRX CW→ multimon-ng→ name → Gold code→ acquire script→ GRC despread→ DBPSK→ frames
    1. File Sink writes one bit per byte; stay_gold_acquire.py --bits scans it
    2. Find the 32-bit sync word 0x1ACFFC1D
    3. Then LEN, LEN ASCII bytes, CRC-16/CCITT over both
    4. Clean frames repeat back to back: FLAG=… NEXT=…, flag 1 and the second name

    Frames run back to back with no gap, SYNC(0x1ACFFC1D) | LEN | ASCII | CRC-16/CCITT: 32 sync bits MSB first, one length byte, LEN bytes of ASCII, then a 16-bit CRC-16/CCITT-FALSE (initial 0xFFFF, polynomial 0x1021, big-endian) over the length byte and the text. Slide a 32-bit window along the bit stream until it equals the sync word, read LEN, take LEN bytes, and keep the frame only if the CRC matches; the pattern then repeats about every 328 bits. The scan is the frames() function in the acquire script, and its --bits mode reads the flowgraph’s File Sink output (one bit per byte) and prints every CRC-clean frame it holds:

    python3 stay_gold_acquire.py --bits stay_gold_bits.u8
# frame: FLAG=flag1{…} NEXT=…

    Signal 1 reads FLAG=flag1{…} NEXT=…: labeled fields, so nobody has to guess which half of a decoded string is which, and the second code is plain. Submit the FLAG field as is (numbered flag1{…}, since two flags share one capture) and carry NEXT to the next frame.

The flowgraph itself was compiled with grcc and run on GNU Radio 3.10.9.2 against the shipped capture: with … and skip 1373 its bit file decodes to flag 1. Our own check is stay_gold/verify_cdma.py, which acquires from the shipped file without the generator’s timing; it recovered 6 CRC-clean frames from signal 1 and still decodes it with 9 dB of extra noise added, so the stage has room for a sloppy receiver.

    Stay Gold · The Blind Sweep and the Symbol Epoch

    sweep 1023 codes→ rank by peak→ epoch sync→ same flowgraph→ frames
    1. G1 all-ones; sweep all 1023 G2 fills, about two seconds
    2. Both signals rank first and second
    3. The hit is the code up to a rotation
    4. Epoch: the one chip shift where every symbol peaks
    5. Skip Head = lag + 4·epoch, same receiver

    A sweep lands on a cyclic shift of the code. The peak stands just as tall, the window straddles symbols, and nothing decodes.

    Without the handover, a player sweeps all 1023 family members with G1 fixed at all-ones (0x3FF) and G2 stepping through every nonzero fill: only the difference of the two fills selects the code, so 1023 (G1, G2) pairs give the same sequence up to a cyclic shift, and this sweep enumerates the whole family once. Score each code by the same FFT correlation as the named path, best block over eight code periods, and rank by peak over median; both transmitted signals rank first and second in about two seconds. This is gold.blind_search in our module and the --blind switch of our verifier; a player writes the same loop around the correlator from the code-phase frame.

    The sweep recovers the sequence only up to a cyclic shift: shift the code by j chips and the correlation lag moves by 4j samples with the same peak height. The named path never meets this, because a name gives the code at rotation zero. At a wrong rotation the correlation window straddles a symbol boundary. It still peaks, and loses height only when the two symbols it spans differ, about half the time, so peak height cannot choose the epoch. In our test, blind search found signal 2 with an acquisition ratio of 4.8 (27.6 with non-coherent accumulation, which did not help) at a lag exactly 460 chips from the true epoch, despread cleanly, and decoded nothing. The second player hint says so: a peak is not an epoch.

    The metric that works is consistency. At the true epoch every symbol correlates to full height; at any other, half dip. gold.epoch_sync (and the epoch() function of the acquire script) multiplies the chip-matched samples by the code once, then gets all 1023 candidate epochs as sliding sums of 1023 chips from one cumulative sum, and keeps the shift with the highest mean magnitude across symbols. Skip Head is then (lag + 4 × epoch) mod 4092, and the flowgraph decodes as before. This is the bit-sync stage every DSSS receiver has, and we kept it as difficulty rather than designing it away: it is the one part of the challenge that punishes a player who stops at “I found a peak”.

    Blind search with no name at all finds both signals, so the handover accelerates and does not gate. A too-easy knob we left unturned: giving signal 2 a code from a different fill of G1 would make the sweep need the epoch stage even to rank it.

    Loiter Mode · Slice at the Preamble Mean

    Slicing at zero, or at the whole burst's mean, corrupts bytes: MAVLink's many zero bytes drag that mean off the offset.

    Correlate the sign of the soft symbols against the 48 preamble and sync bits at each symbol phase and keep the phase with the highest peak.     Red Coast · Sync on the Preamble

    whole-band power vs time→ sync on 1010 preamble→ threshold about the mean→ CyberChef ASCII
    1. Divide the power by its mean and subtract 1; the symbols sit at ±0.05
    2. Correlate against 32 alternating bits, 10 000 samples each; the peak is the preamble start
    3. Average each 10 000-sample slot from there; threshold at zero
    4. Drop the 32 preamble bits; 632 payload bits remain

    Symbol timing comes from the preamble, not from prior knowledge: matched-filter the alternating 32-bit preamble against the normalized power at full sample resolution, and the correlation peak locates the preamble start to within 11 samples of a 10 000-sample symbol. From there every slot is one symbol, and the threshold is the mean, which the normalization put at zero.

    p = np.abs(seg2.astype(np.complex128))**2
z = p / p.mean() - 1.0
ref = np.repeat(np.tile([1.0, -1.0], 16), 10_000)
start = np.argmax(fftconvolve(z, ref[::-1], mode="valid"))
n = (len(z) - start) // 10_000
sym = z[start:start + n * 10_000].reshape(n, 10_000).mean(axis=1)
bits = (sym > 0).astype(int)[32:32 + 632]

    That is the whole receiver: no tuning, no filtering, no demodulation. At full bandwidth the shipped build decodes with 0 errors in 664, and 0 in 5312 across 8 seeds.

    import numpy as np

# x: complex IQ samples; fs: sample rate
f, t, S = spectrogram(x, fs, nperseg=4096, return_onesided=False)

    two pages, two table numbers→ diff the bits in URH→ edit address, fix checksum→ transmit→ named pager only
    • Capture pages differing only by table number
    • Diff the demodulated bits: the address field
    • Synthesize any number and transmit
    • Flag 2 proves the addressing, not just the framing

    An all-call rings everything. For flag 2 only the named pager may alert, twice, with two numbers.

    Isolate the address. Capture two pages that differ only in table number and line up their demodulated bits; URH can mark the differing positions directly. If the frame carries a checksum, work out how it follows the address and recompute it.

    Synthesize. Rebuild the page for an arbitrary number, keeping the preamble, timing and repeat count of the captures, and transmit it from URH's generator or a GNU Radio flowgraph into the same HackRF or Pluto. On a PT2262/EV1527-style encoder this is a direct edit of the address bits.

    The judge. An organizer names a number the player has not used; only that pager may alert; then a second, different number, with no stray units. That rules out broadcast and keeps a shared capture from handing out flag 2. The judge keeps three or four labeled spare pagers behind the desk to call unpredictable numbers. Because it is live transmit, organizers asked players to stay low-power and in-room and not to hammer the band.
